# Electron 桌面端多账号浏览器方案（交接文档）

## 一、项目目标

开发一个跨平台（Windows、macOS、Linux）的桌面应用程序，用于在同一台电脑上同时登录多个网页游戏账号，实现账号环境完全隔离，并支持油猴脚本扩展。要求资源占用尽可能低，且具备一定的反关联能力。

---

## 二、技术选型：Electron

**选择理由：**
- 基于 Chromium，可直接加载 Chrome 扩展（如 Tampermonkey），满足油猴需求。
- 提供 `session` 分区机制，天然支持多账号存储隔离。
- 跨平台一致性好，前端使用 HTML/JS，开发效率高。
- 生态成熟，打包分发方便（electron-builder）。

**替代方案对比：**
- Tauri：资源占用低，但 WebView 对 Chrome 扩展支持差，无法直接运行油猴。
- 原生 WebView2：仅限 Windows，跨平台能力弱。
- 便携版浏览器 + 启动器：无需开发，但用户体验和封装程度低。

**最终选择 Electron 兼顾功能与开发效率。**

---

## 三、整体架构

### 3.1 单实例应用，多窗口管理
- 应用启动后展示一个**主控制台窗口**，用于管理账号（添加、删除、启动、停止）。
- 每个账号对应一个独立的 `BrowserWindow`，窗口尺寸默认设为手机分辨率（如 360×640）。
- 所有账号窗口共享同一个 Electron 主进程，但各自使用**独立的 session 分区**，实现存储隔离。

### 3.2 Session 分区设计
- 使用 `session.fromPartition('persist:account_<ID>')` 为每个账号创建持久化分区。
- 每个分区拥有独立的 `Cookies`、`Local Storage`、`IndexedDB`、缓存等。
- 油猴扩展在每个分区中**单独加载**，脚本数据互不影响。

### 3.3 资源优化策略
- **窗口尺寸**：默认 360×640，可由用户调整，但建议限制最大 800×600。
- **禁用 GPU 加速**：在应用启动时调用 `app.disableHardwareAcceleration()`，减少 GPU 进程内存。
- **限制渲染进程数**：`app.commandLine.appendSwitch('renderer-process-limit', '1')`，减少子进程数量。
- **禁用后台页面节流**：`webPreferences.backgroundThrottling = false` 可保持游戏运行，但会增加资源占用，按需开启。
- **内存限制**：通过 `webPreferences` 或 `app.commandLine.appendSwitch('js-flags', '--max-old-space-size=256')` 限制 V8 堆大小（需测试兼容性）。

## 四、账号隔离实现细节

### 4.1 基本隔离
每个账号窗口创建时指定独立的 `partition`：

```javascript
const { BrowserWindow } = require('electron');

function createAccountWindow(accountId, url) {
  const win = new BrowserWindow({
    width: 360,
    height: 640,
    webPreferences: {
      partition: `persist:account_${accountId}`, // 关键：独立分区
      nodeIntegration: false,
      contextIsolation: true,
      backgroundThrottling: false, // 防止后台暂停
      // 可选：开启 offscreen 渲染（不推荐，消耗大）
    }
  });
  win.loadURL(url);
  return win;
}
```

### 4.2 IP 隔离（防关联）
Electron 本身不提供代理隔离，需要为每个账号窗口的 session 设置独立代理：

```javascript
const ses = win.webContents.session;
await ses.setProxy({
  proxyRules: `http=代理IP:端口;https=代理IP:端口`,
  proxyBypassRules: '<local>'
});
```

- 推荐使用 **SOCKS5 或 HTTP 代理**，每个账号分配一个独立出口 IP。
- 若使用系统代理，需注意所有窗口会共享，无法隔离。
- 可在账号配置中存储代理信息，启动窗口前设置。

### 4.3 浏览器指纹伪装
仅靠 session 分区无法改变指纹，需通过以下方式降低关联风险：

| 指纹项 | 修改方法 |
|--------|----------|
| User-Agent | `ses.setUserAgent('自定义 UA 字符串')` |
| 屏幕分辨率 | 设置窗口尺寸不同，或注入 JS 覆盖 `screen` 对象 |
| Canvas/WebGL | 注入 JS 在 `html` 加载前修改相关 API（可参考 `puppeteer-extra-plugin-stealth` 的指纹扰动代码） |
| 时区/语言 | 通过 `app.commandLine.appendSwitch('lang', 'zh-CN')` 或注入 JS 修改 `Intl` 和 `Date` 对象 |
| 硬件并发数 | 注入 JS 覆盖 `navigator.hardwareConcurrency` |
| 设备内存 | 注入 JS 覆盖 `navigator.deviceMemory` |
| WebRTC 泄露 | 设置 `app.commandLine.appendSwitch('force-webrtc-ip-handling-policy', 'disable_non_proxied_udp')`，或注入 JS 禁用 WebRTC |

**建议**：使用一个专门的**指纹随机化模块**，在窗口创建时注入脚本，为每个账号生成不同的指纹参数。可参考开源项目 `fingerprint-injector` 或自行实现。

### 4.4 油猴插件集成

#### 4.4.1 加载扩展
```javascript
const path = require('path');

async function loadTampermonkey(sessionPartition, extensionPath) {
  const ses = session.fromPartition(sessionPartition);
  const ext = await ses.loadExtension(extensionPath, { allowFileAccess: true });
  console.log(`Tampermonkey loaded for ${sessionPartition}:`, ext.id);
}
```

- **extensionPath** 为 Tampermonkey 解压后的目录（需包含 `manifest.json`）。
- 从 Chrome 商店下载 CRX 后解压，或从已安装的 Chrome 扩展目录复制（注意版本兼容性）。

#### 4.4.2 多分区独立
因为每个账号使用独立的 `session.fromPartition`，扩展的数据（脚本列表、存储）也是隔离的。需要在每个账号窗口创建前，对该分区调用 `loadExtension`。

#### 4.4.3 自动化安装脚本
若需要为新账号自动安装特定脚本，可在扩展加载后，通过 `ses.executeJavaScript` 访问 Tampermonkey 的存储并写入脚本（较复杂），或引导用户手动导入。简单做法：首次创建账号时打开 Tampermonkey 选项页，让用户导入脚本包。

## 五、主控制台与账号管理

### 5.1 主窗口功能
- 账号列表展示（名称、状态、代理信息）。
- 添加/删除/编辑账号。
- 启动/停止账号窗口。
- 批量操作（启动全部、停止全部）。
- 查看资源占用（可选：通过 `app.getAppMetrics()` 获取进程信息）。

### 5.2 数据持久化
- 使用本地 JSON 文件或 `electron-store` 保存账号配置（ID、名称、URL、代理、UA等）。
- 账号的浏览数据（cookies、localStorage）保存在 Electron 用户数据目录下的 `Partitions/account_<ID>` 文件夹中，无需手动管理。

### 5.3 窗口生命周期
- 关闭账号窗口时，可选择仅隐藏（保留后台运行）或完全关闭（释放资源）。
- 提供“最小化到托盘”功能，减少任务栏占用。

## 六、开发与部署注意事项

### 6.1 开发环境
- 安装 Node.js（建议 v18+）、npm/yarn。
- 初始化 Electron 项目：`npm init -y && npm install electron --save-dev`。
- 使用 `electron-builder` 打包，配置文件支持 Windows NSIS、macOS DMG、Linux AppImage。

### 6.2 打包与分发
- 将 Tampermonkey 扩展目录放入项目资源中，打包时通过 `extraResources` 包含。
- 代理配置等信息不应硬编码，应由用户填写。
- 注意应用签名问题：未签名应用在 macOS 上可能被 Gatekeeper 阻止，Windows 上可能被 SmartScreen 警告。

### 6.3 安全性
- 主窗口与账号窗口之间通信使用 IPC，需严格校验消息来源。
- 禁用 `nodeIntegration`，启用 `contextIsolation`，防止游戏页面访问 Node.js 环境。
- 代理密码等敏感信息加密存储（使用 `safeStorage` API）。

## 七、性能预估与优化

在 2 核 4G 的典型服务器/PC 上：
- 每个 Electron 账号窗口（含油猴）约占内存 150~250 MB（手机分辨率、禁用 GPU）。
- 可同时运行 **4~6 个**账号窗口（取决于游戏复杂度）。
- 通过限制渲染进程和 V8 堆，可进一步压缩至 120~200 MB。

**进一步优化建议：**
- 使用 `--disable-software-rasterizer` 减少 CPU 占用。
- 关闭窗口动画：`win.setMenuBarVisibility(false)`。
- 对于不活跃的账号窗口，可设置 `webContents.setBackgroundThrottling(true)`（但可能导致游戏暂停）。
- 定期监控内存，必要时通过 `webContents.reload()` 释放泄漏。

## 八、已知限制与风险

1. **浏览器指纹伪装有限**：Electron 无法像专业指纹浏览器一样彻底改变底层指纹（如 Canvas 硬件级差异），需要持续注入 JS 进行扰动。
2. **油猴扩展兼容性**：部分油猴脚本可能依赖 Chrome 特有 API，在 Electron 中可能运行异常，需测试。
3. **系统资源占用**：与原生浏览器相比，Electron 每个实例仍有额外开销，但已优于 Docker 容器方案。
4. **反作弊检测**：即使做了 IP 隔离和指纹随机化，仍可能被高级风控系统识别，建议配合住宅代理使用。
5. **跨平台差异**：macOS 上某些命令行开关可能无效，需针对平台适配。

## 十、总结

本方案采用 Electron 构建多账号浏览器桌面端，利用 session 分区实现账号隔离，支持油猴扩展，并通过窗口尺寸控制、禁用 GPU、限制进程等手段降低资源占用。同时提供了 IP 隔离和指纹伪装的基本思路，以应对游戏平台的反关联检测。该方案平衡了开发效率与资源消耗，适合需要手动操作、多账号同时在线且依赖油猴脚本的场景。

**交接要点：**
- 核心代码位置：主进程 `main.js`（窗口管理、session 加载）、`fingerprint.js`（指纹注入）、`proxy.js`（代理设置）。
- 扩展目录：`resources/tampermonkey/`。
- 账号配置存储：`userData/accounts.json`。

请接手者首先阅读项目 README，并运行 `npm install` 安装依赖，开发模式使用 `npm start` 启动。
